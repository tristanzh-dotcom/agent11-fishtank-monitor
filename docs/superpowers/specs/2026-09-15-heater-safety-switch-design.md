# 冬季电热棒外层温控设计

日期：2026-09-15

状态：核心控制规则已由 TZ 在本任务中明确同意；本文完成设计记录，尚未实现。第 6 节为执行细节建议，第 7 节为硬件实施前提，不代表已完成设备选型或获得刷写、配对及市电操作授权。

## 1. 目标与已批准决定

电热棒自身负责正常恒温，Agent11 使用现有水温探头和成品可控插座，持续执行外层宽温差控制：达到上限断电，降到下限恢复供电，中间区间保持原状态。

TZ 已批准：

- L 复用对应鱼缸的低温 N2 数值，H 复用高温 N2 数值。
- 通断电只借用温度数值，不继承 N2 的 15 分钟告警等待时间。
- 每次开关动作均通过设备直连 Bark 通知；控制失败或结果未知须如实表达。
- 既有 N2、N3 温度告警规则、持续时间、恢复条件和提醒频率保持原样。
- 无需手动确认维修，不设置“正常／接管／恢复”模式或恢复观察计时。

这组决定替代此前讨论中的“两级高温断电”“高温永久锁定”“正常 15 分钟退出接管”及“统一最小开关间隔 5 分钟”建议。

当前项目仍是只监测系统。本文记录未来增加加热插座控制的设计，不将现有 README、AGENTS 或已部署固件描述成已具备控制能力。

## 2. 控制参数与测点

| 鱼缸 | 控制测点 | L：恢复供电 | H：断电 | 既有低温／高温 N3 数值 |
| --- | --- | ---: | ---: | ---: |
| 包包缸 | 主缸探头 | 23.5°C | 27.5°C | 22.5 / 28.5°C |
| 老四缸 | 本缸探头 | 22.5°C | 27.5°C | 20.5 / 28.5°C |
| 小黑缸 | 本缸探头 | 23.5°C | 27.5°C | 22.5 / 28.5°C |
| 毛毛缸 | 本缸探头 | 23.5°C | 27.5°C | 22.5 / 28.5°C |

参数来源为 [TemperaturePolicy](../../../lib/temperature_engine/include/temperature_engine.hpp) 和 [各缸配置](../../../include/config.hpp)。控制器直接使用该缸策略字段，避免另一份可独立编辑的阈值副本。

正常电热棒设定应位于 L 与 H 之间，并留出正常波动余量；本设计不自动修改电热棒设定。这里复用的是现有告警参数，并非新增物种适温结论。实际温度波动和是否误动作须现场验证。

包包缸底滤探头继续用于既有循环诊断，不取主缸与底滤的平均值，不因主缸探头失效而自动换用底滤测点。加热棒若装在底滤，应核对循环停止时主缸测点是否仍能反映受热位置；本方案不能据此声称覆盖局部过热或干烧。

## 3. 唯一日常控制规则

本表用于已启用、探头绑定正确且取得有效新鲜读数的回路。异常数据和启动行为见第 6 节。

| 条件 | 控制动作 |
| --- | --- |
| T >= H | 目标为断电；记录“高温断电保持”，直到降至 L 才解除 |
| T <= L | 目标为通电；解除本轮高温断电保持 |
| L < T < H | 保持当前目标；高温断电保持期间不得因温度回到中间区间而通电 |

在相等处也触发，使用未按 UI 小数位四舍五入的有效读数。目标状态未变时，不生成重复开关事件；确认或重试命令不算新一轮动作。

“立即”指拿到超限读数后不再等待持续时间，优先执行控制。现有采样配置为约 30 秒；实际总延迟包含采样间隔、网络调用、探头响应和水流影响，不能承诺严格 30 秒或 33 秒内断电。L/H 是动作触发点，不能承诺真实水温绝不越界。

自然运行结果：

1. 电热棒正常：自行在设定值附近停止加热，外层插座通常持续供电。
2. 电热棒持续加热：升到 H 后断电，降到 L 后通电，反复执行并逐轮通知。
3. 电热棒不加热或加热不足：保持供电，由既有持续低温规则发出告警；反复开关不能创造热量。
4. 电热棒修复或更换：若插座处于高温断电保持，仍等到 L 才恢复供电；随后电热棒自行恒温，外层自然不再动作，不发布“确认修好”的推断。

## 4. Bark 与既有告警

每次新开关动作建立一条通知记录，包含鱼缸、触发时温度、阈值、方向、原因和执行结果。完成状态核对后发送结果；核对超时则报告结果未知，后续确认可补发结果更新。

- 高温断电：表达“达到上限，插座报告关闭”。
- 降温恢复供电：表达“降到下限，插座报告开启；继续监测”。
- 控制失败／未知：表达“已请求开／关，执行结果未确认”。不能把请求成功写成负载已物理断电。
- 温度无效：写“无有效读数”，不得用历史温度或零值代替。

同一动作的控制重试不生成新的阈值通知；下一次真实加热／降温周期必须再次通知。持续低温、N3 和传感器故障继续使用既有事件生命周期，不能每次采样都重发。

既有 N3 仍是严格越限并持续 5 分钟，不能把本方案写成“N3 一到就立即推送”。新开关事件独立于原 N2/N3 事件；两个事件可在各自条件满足时分别通知。刚触及 L 并恢复供电不等于已经确认电热棒损坏。

控制决策及命令优先于 Bark 发送。Bark 失败不撤销控制、不阻止下一轮判定；通知采用有界排队和失败重试，具体复用点在实现前确定。网络中断时无法保证每条消息即时到达手机，HTTP 成功也不等于手机已显示或用户已读。沿用既有事件时间／发送时间表达及未校时降级规则。

## 5. 最小系统范围

数据路径：对应鱼缸 DS18B20 → Agent11 本地规则 → 本地网络插座；动作结果 → 既有直连 Bark。

Agent11 是唯一控制方。温度输入使用原始本地采样，不解析手机温度摘要，不经 Tab5、电脑、云服务或模型判断。Tab5 继续展示现有水温；本版不增加插座控制页面、维修确认入口、历史曲线或新的公共状态协议。

先以一个明确绑定的鱼缸／插座回路验证；四缸参数表不等于已授权同时启用四个回路。每个回路只控制本缸加热设备，不连带切断水泵、过滤、Agent11 电源或其他鱼缸设备。

## 6. 执行细节建议与能力边界

以下是使方案可落地的候选处理，不冒充 TZ 已逐项批准的运行行为；实施前随选型和故障用例一起确认。

### 数据、重启与恢复

- 只允许正确绑定的探头、新完成的有效转换结果驱动控制；重复旧读数不能刷新有效期。
- 读数无效或过期时请求断电、暂停通电许可，并报告监测不可用；无法读回结果时维持“未知”。该选择优先限制失控加热，但可能导致冬季降温，不能宣称兼顾两种故障。
- 跨重启保留最小的“高温断电保持”标记，不建设通用维修模式或历史数据库。高温时先请求断电并保存标记；存储失败时停止通电许可并报告故障。
- 重启先核对存储、当前有效读数与插座状态。标记存在时维持断电至 T <= L；无标记且 T < H 时允许恢复原来的正常供电；T >= H 时断电并建立标记。缺少可靠数据或存储不可读时不自动通电。
- 探头数据恢复后自动重新判定，但不得越过已有高温断电保持条件。无需用户确认修复。

### 插座失联与通信

- 使用明确的“设为开启／关闭”命令，避免使用翻转命令。重试前重新核对当前温度及目标，旧的开启请求不得在新高温判定后继续重试。
- 选型应验证本地鉴权、状态读回和插座自身的限时供电能力。通电许可只能由新鲜有效读数续期；Agent11 停止采样、失电或网络失联后，插座应能自行到期断电。
- 许可有效期、续期间隔、数据有效期及请求总超时需作为一组参数，通过具体设备的断网和负载测试确定并补入实施规格。当前未选定插座，不承诺任何固定失联断电秒数。只有普通本地开关 API、没有可靠本机超时的插座，不能宣称满足这项失联保护。
- 插座自身定时和普通日程必须区分：关闭会绕过温度许可的自动开启日程，保留经过验证的到期断电机制。断网、控制器重启和插座重启都要验证。
- 插座报告的开关状态不证明继电器触点实际断开，也不证明电热棒正在发热。功率测量可帮助诊断，但不是本版新增硬件要求。探头脱离水体却读数合理、探头偏差及继电器粘连均不属于单探头网络开关方案已解决的问题。

## 7. 最小硬件与采购前输入

| 项目 | 新增数量 | 要求 |
| --- | ---: | --- |
| 成品本地可控插座 | 每个独立受控回路 1 个 | 匹配供电和插头制式；厂家允许对应加热负载及持续运行；本地开关、鉴权、状态读回；核验第 6 节的本机超时能力 |
| Agent11 主控及对应水温探头 | 0 | 复用现有设备并核实本缸物理绑定 |
| Tab5、电脑、网关或新增云服务 | 0 | 不作为控温必要设备 |
| 独立探头高温保护器 | 可选 | 覆盖独立测温／切断需求时另行评估，不列为本版必购物料 |

采购和启用前需取得：首个试点鱼缸、实际水量、加热棒数量／总功率／设定温度／安装位置、拟选插座型号。用这些信息核对正常温度与 L/H 的关系、升温速度、采样和控制延迟造成的余量，以及回路额定负载。未核对前不指定采购型号、价格或固定电流余量倍数。

使用成品插接设备，不提供裸继电器市电接线方案。当前设计不授权配对、改变插座配置或接入真实加热回路。

## 8. 验证与完成标准

本轮仅设计文档，采用 Level 0：核对源参数、条件完整性、链接和变更范围；不运行固件构建或设备操作。

后续实施按实际受影响范围验证：

1. 规则：精确 L/H、区间保持、重复读数、无效／过期、持续失控加热循环、修复后自然不再开关、已供电仍低温、四缸阈值和身份不混用。
2. 执行：开关结果确认、重复命令不翻转、旧通电请求不覆盖新断电决定、Bark 失败不拖延控制、重启保持及存储失败处理。
3. 设备：验证本地通信不依赖外网；断网、Agent11 停止采样及插座重启时，本机超时行为符合已补齐的秒数指标。
4. 现场：先用无鱼的测试环境验证温度输入及开关，再经单独授权接入目标回路，测量实际温度波动、响应时间和每轮 Bark；验证不得通过人为加热有鱼水体到危险温度进行。

规则测试、目标构建、插座回报、真实断电、手机送达与现场持续运行分别记录。本文不是这些验收已通过的证明。
