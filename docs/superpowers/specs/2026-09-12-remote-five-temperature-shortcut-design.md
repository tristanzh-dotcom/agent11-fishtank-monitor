# 外网 iPhone 快捷指令五缸温度查询设计

**日期：** 2026-09-12

**状态：** 已按复审意见和 TZ 确认的十分钟过期规则修订，待实现

**项目：** Agent11 Fish-Tank Monitor

## 1. 目标

在现有五探头本地监测、Bark 告警和每日温度汇总的基础上，增加一个单一的远程只读
查询能力：用户在 iPhone 15 Pro Max 上通过一个手动“快捷指令”，即使手机不在家庭
Wi-Fi 内，也可以查看四套鱼缸、五个温度点最近一次温度信息。下文“五缸摘要”沿用
现有文案简称；包包缸主缸与回水缸属于同一套鱼缸。

远程数据允许约 5 分钟滞后。手机显示内容复用现有日报正文格式：

- 包包缸（主缸 / 回水缸）；
- 老四缸；
- 小黑缸；
- 毛毛缸；
- 采样时间；
- 当前采样时的高低温分类、无效读数或配置状态。

## 2. 范围与非目标

### 2.1 本期范围

- 复用现有 ESP32 五路采样和约 5 分钟心跳上传节奏；
- 将最新五缸日报正文作为私有心跳快照的一部分上传；
- 复用现有腾讯 SCF、COS 最新状态对象和只读 Bearer Token；
- 在现有 Function URL 上增加一个私有只读温度摘要 GET 路径；
- iPhone 使用一个手动快捷指令发起 HTTPS GET 并显示纯文本结果。

### 2.2 明确不做

- 不开发原生 iOS App，不使用 Xcode，不上架 App Store；
- 不增加 Web Agent 页面，不修改现有 `FishTankStateV1` 公共状态；
- 不修改既有 Bark 告警、定时 Bark 日报或告警文案；
- 不增加历史数据库、图表、趋势分析或自动化通知；
- 不增加任何控制 ESP32、加热棒、水泵或市电设备的能力；
- 不开放家庭路由器端口，不让手机直接暴露访问 ESP32；
- 不使用 Tab5 局域网广播或修改 Tab5 功能；
- 不建立新的云服务、定时任务或第三方手机服务。

本功能唯一新增的跨层行为，是为手机远程读取而保存和返回最新五缸快照。
这是对原五探头设计中“小缸不进入云端”边界的限定扩展：仅允许摘要经既有腾讯云
SCF/COS 保存并向已认证的手机查询返回，小缸告警事件仍不进入公共状态或云端告警。

## 3. 当前基线

当前实现已经具备以下可复用能力：

- ESP32 每约 30 秒读取五个固定 ROM 的 DS18B20；
- 现有心跳约每 5 分钟发送一次到腾讯 SCF；
- 心跳使用现有设备密钥和 HMAC 签名，云端保存 COS 中一份最新状态；
- 现有 Function URL 已有 Bearer Token 保护的只读 GET；
- `daily_summary_body` 已统一生成五缸日报正文；
- 当前心跳字段只有主缸、回水缸和既有主缸事件，三个小缸不会进入当前公共状态投影。

因此，本方案复用现有心跳上行链路和只读认证，不另建 ESP32 到云端的上传通道。

## 4. 方案比较与选型

### 4.1 方案 A：复用现有心跳 + 私有温度摘要 GET（采用）

ESP32 在心跳需要发送时用本轮五路采样生成日报正文，随既有约 5 分钟心跳上传。SCF 将正文保存
在同一份最新状态对象中，手机快捷指令通过现有只读 Token 查询一个新的温度摘要路径。

优点：复用当前设备联网、签名、COS、Function URL 和 Token；手机端不需要开发 App；
不触碰 Web Agent 和现有公共状态。缺点：远程结果受心跳节奏影响，不能保证 30 秒级
新鲜度。

### 4.2 方案 B：家庭 VPN + ESP32 局域网接口

手机先通过 WireGuard 等方式进入家庭网络，再访问 ESP32 的局域网接口。

该方案可以接近 30 秒采样新鲜度，但需要家庭路由器或常驻设备支持 VPN，并且仍需
新增 ESP32 HTTP 服务。本期接受约 5 分钟滞后，不选用。

### 4.3 方案 C：家庭路由器端口转发

直接把 ESP32 或家庭 HTTP 服务暴露到公网。

这会引入公网端口、TLS、认证、扫描和维护风险，且不复用现有安全链路，排除。

## 5. 选定架构

### 5.1 数据流

```text
五探头采样（ESP32）
        |
        | 每约 5 分钟随既有 HMAC 心跳上传
        v
腾讯 SCF -> COS 最新状态对象
        |
        | HTTPS GET + 只读 Bearer Token
        v
iPhone 快捷指令 -> 显示日报格式纯文本
```

### 5.2 ESP32 最新快照

每次五路采样完成时记录该轮 Unix 毫秒时间。仅在本轮需要发送心跳时，使用这份
读数和现有日报格式化逻辑生成摘要；不每 30 秒生成正文，不增加长期正文缓存。
定时日报和心跳摘要复用同一份格式化逻辑，正文时间与 `sampled_at_ms` 必须来自
同一采样时刻。心跳失败后的下一次尝试使用新一轮读数，不重放旧摘要。

心跳增加一个仅用于私有远程读取的可选字段：

```json
{
  "temperature_snapshot": {
    "sampled_at_ms": 1789203600000,
    "summary_text": "采样时间：..."
  }
}
```

上例仅表示字段形状，不是真实采样；实现时正文时间由同一个 `sampled_at_ms` 转换
为上海时间。采样时间必须是有效 Unix 毫秒整数，不能使用设备启动后的毫秒数。

- `sampled_at_ms` 是这份五路数据的实际采样时间，不使用心跳发送时间替代；
- `summary_text` 是现有日报正文，不包含设备密钥、Token、Wi-Fi 或 CA；
- 正文继续使用一位小数、固定鱼缸名称和现有无效/状态文案；
- `summary_text` 限定为非空且最多 768 个 UTF-8 字节；云端检查类型、字节长度及采样
  时间有效性。整体心跳按 JSON 转义后的实际 UTF-8 字节数检查，仍不得超过 2048 字节；
- 实现测试须覆盖最长合法日报、最多七条现有事件和最大合法字段长度组合。若固件
  生成的摘要超限，只省略整个可选摘要字段，继续发送原有心跳，不截断正文或丢弃事件；
- 新增字段包含在现有原始 JSON 哈希和 HMAC 签名范围内，不能脱离设备认证单独修改；
- 时间未校准或采样没有有效时间时，不伪造采样时间，不上传一份被称为“当前”的快照。

该字段是为本功能增加的私有心跳扩展，不改变现有 `/state` 响应、`FishTankStateV1`
或 Web 公共语义。

### 5.3 云端保存与读取

SCF 在现有最新状态对象中保存 `temperature_snapshot` 的内部字段。现有状态对象仍只
保留一份最新值，不建立按时间增长的历史记录。

新增字段可缺省，以兼容旧固件。每次通过认证的有效心跳覆盖状态时，没有摘要字段就
清除上一份摘要，不能给旧摘要配上新心跳时间。字段存在但格式非法时按既有请求校验
规则拒绝；旧状态对象没有该字段视为“暂无温度数据”。沿用内部 `schemaVersion: 2`
并添加可选字段；离线定时检查更新状态时保留该字段，现有 `/state` 投影忽略它。

新增精确只读路径：

```text
GET /api/v1/devices/tank01/temperature-summary
```

接口规则：

- 继续使用现有 `STATE_READ_TOKEN` 对应的 Bearer Token；
- Token 只能放在 `Authorization` 请求头，不能放入 URL、响应正文或日志；
- 认证成功且状态可读取时返回 `200` 和 `text/plain; charset=utf-8`：数据可用时正文
  就是 `summary_text`；过期、离线或暂无数据时正文为第 6 节中文提示，不含旧温度。
  此处 `200` 表示查询处理成功，不表示设备在线或温度可用；
- 响应设置 `Cache-Control: no-store`，避免手机或中间层显示缓存内容；
- 现有 `GET /api/v1/devices/tank01/state` 保持原 JSON 和字段不变；
- 新摘要路径认证失败返回 `401`，非 GET 返回 `405`，存储读取失败或状态损坏返回
  `503`，错误正文使用简短中文且不含温度或内部信息；其他路径保持既有路由行为。
  新摘要路径按精确路径分流，不能让 POST 落入原心跳处理器；
- 每次 GET 都按服务端当前时间检查采样年龄，不能只依赖存储中的在线标记；
- 云端不重新计算温度告警，不根据温度值推导新的事件。

正文保留“采样时间”，云端按第 6 节规则判断是否允许返回温度。GET 不更新 COS、不
刷新设备在线时间、不触发 Bark。复用只读 Token 意味着其现有持有者也可读取新摘要，
它不是手机专属权限；本期不增加另一套 Token 管理。

### 5.4 iPhone 快捷指令

仅配置一个手动快捷指令，建议名称为“查看鱼缸温度”：

1. 使用“获取 URL 内容”动作；
2. URL 使用上述 HTTPS GET 路径；
3. 方法选择 `GET`；
4. 在 Headers 中加入 `Authorization: Bearer <只读 Token>`；
5. 使用“显示结果”动作显示返回纯文本；
6. 可将快捷指令添加到主屏幕，便于一键查看。

快捷指令通过手机蜂窝网络访问云端，不要求手机与 ESP32 处于同一 Wi-Fi。它只发起
读取请求，不发送 Bark，不发送控制命令，也不修改任何设备状态。
过期、离线和暂无数据由云端直接返回中文文字，手机无需解析 JSON 或重复计算年龄。
手机断网、超时或快捷指令遇到 HTTP 错误而中止时，允许使用系统错误提示；不承诺所有
网络异常都能经过“显示结果”动作，不增加自动重试或手机本地温度缓存。

## 6. 数据新鲜度与异常边界

- ESP32 本地采样仍约每 30 秒一次；
- 云端更新仍跟随现有约 5 分钟心跳；
- 正常更新周期约 5 分钟，不是严格延迟上限；采样调度和网络重试可能使数据更旧；
- 返回正文保留实际 `采样时间`，不得用云端读取时间冒充采样时间；
- 心跳失败时，云端不会得到新快照；
- 查询判断顺序：先认证和检查存储状态，再检查离线、摘要存在性及有效性、采样年龄。
  设备已标记离线时优先显示“设备已离线，温度信息暂不可用。”，不显示旧温度；
- 无摘要时显示“暂无温度数据，请稍后重试。”；摘要损坏或采样时间在服务端未来时
  视为数据不可用，不作为新鲜温度返回；
- `服务端当前时间 - sampled_at_ms > 600000` 时，仅显示
  “温度数据暂未更新，最后采样时间：YYYY-MM-DD HH:mm:ss（上海时间）”，不拼接旧
  日报正文、不显示任何旧温度。恰好 10 分钟时尚未过期；
- 采样年龄不超过 10 分钟且其余检查通过时返回原摘要。该规则独立于现有默认
  15 分钟离线判定及其 Timer，不调整离线告警阈值，也不写入新的在线/离线状态；
- 不为远程查询增加补发、历史回放或独立缓存队列；
- Bark 告警和 09:00/18:00 定时日报继续按原有本地规则运行，互不依赖手机查询。

## 7. 安全与兼容性

- ESP32 到 SCF 继续使用现有 HMAC 设备认证和 HTTPS；
- 手机到 SCF 继续使用现有只读 Bearer Token；
- 远程接口只有 GET 读取能力，没有写入或设备控制能力；
- 不在代码、文档、URL、日志或测试输出中保存真实 Token、设备密钥、Wi-Fi 或 CA；
- 新增的私有心跳字段不进入 `FishTankStateV1`，不改变 Agent12/Web；
- 现有主缸/回水缸心跳字段、事件快照、Bark 告警和 Tab5 功能保持原样；
- 手机 Shortcut 中的 Token 属于敏感配置，不分享快捷指令，不把 Token 作为 URL 参数。

## 8. 实现边界与最小测试

### 8.1 固件和传输合同

- 扩展心跳 C++ 载荷和序列化，覆盖 `temperature_snapshot`；
- 将最新五缸快照接入现有心跳调用，不改变采样、告警、日报调度和心跳频率；
- 复用现有日报格式化逻辑，不复制一套手机专用文案；
- 主机测试覆盖字段缺失、采样时间与正文一致、无效时间、768 字节正文边界、完整
  心跳 2048 字节边界、超限省略摘要、JSON 转义和签名输入变化；
- 保留现有主缸/回水缸心跳合同回归。

### 8.2 SCF

- 心跳合同测试覆盖合法/非法 `temperature_snapshot`；
- 心跳处理测试确认快照只覆盖最新对象、旧固件心跳清除旧摘要、Timer 保留摘要；
- 只读接口测试覆盖正确/错误 Token、错误路径、非 GET、无快照、离线、未来时间、
  恰好 10 分钟与超过 10 分钟、纯文本响应及无 COS 写入/Bark 调用；
- 现有 `/state` 输出测试必须保持通过；
- 错误响应不得包含 Token、密钥、原始请求头或内部异常。

### 8.3 手机与现场验收

- 在 iPhone 上配置并手动运行快捷指令；
- 关闭 iPhone Wi-Fi，使用蜂窝网络请求成功；
- 可用结果包含四套鱼缸的五个温度点、采样时间和已确认的状态/无效提示；
- 对比 Bark 定时日报，正文格式和一位小数规则一致；
- 在设备正常运行时观察约 5 分钟新鲜度；
- 在受控测试中确认过期/离线结果没有旧温度，手机断网时不会显示上一次查询结果；
- 确认 Web Agent 页面、Bark 告警和设备控制行为没有新增或变化。

## 9. 实施顺序

1. 先实现并测试私有心跳快照字段和温度摘要 GET；
2. 从项目目录完成主机合同测试和目标固件构建；
3. 先部署兼容旧固件的云端，确认现有只读 Token 和 `/state` 回归，新接口此时允许
   返回“暂无温度数据”；
4. 再刷写不含 Tab5 功能的目标固件，确认五路读数及新心跳摘要上传后，在 iPhone
   上建立快捷指令；不恢复或修改工作区内既有 Tab5 功能；
5. 使用蜂窝网络完成一次远程读取验收。

任一阶段失败时，不改变 Bark 告警和现有 Web/心跳公开合同来绕过问题。

## 10. 验收结论

本设计只新增一个能力：通过 iPhone 快捷指令远程读取最新五缸温度摘要。其余系统行为
保持不变。验收通过的必要条件是：

- 手机不在家庭 Wi-Fi 时可以一键取得五缸日报格式文本；
- 正文使用真实采样时间，正常更新周期约 5 分钟；
- 既有 Bark 告警、定时日报、Web Agent 页面、`FishTankStateV1` 和 Tab5 均未被扩展；
- 无效、离线或未授权状态不会被伪装成有效当前温度。

本轮授权范围为设计修订；上述实施顺序不表示已执行代码修改、云端部署或刷写。
TZ 已确认：采样超过 10 分钟仅显示未更新提示与最后采样时间；已判定离线时显示
不可用，均不展示旧温度。
